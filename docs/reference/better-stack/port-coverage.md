# Port coverage: what the reference has and we deliberately do not

Recorded 2026-11-14. Every entry below is a reference feature with no equivalent in Uptimer, kept out on purpose rather than because it was forgotten. The reasons are technical, not cosmetic.

| Reference feature                                                                                                                                                           | Where it appears                                                                       | Why it is not ported                                                                                                                                                                                                                                                                            | If it is ever wanted                                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **On-call schedules and escalation policies** — primary responder, escalation policy select, "if the primary responder doesn't acknowledge" steps, Escalation steps section | Create/Configure monitor, Create heartbeat, bulk _Configure on-call escalation_        | Uptimer has one team and no on-call rota or policy model. Alerts go to every enabled webhook channel, or to the channels the monitor selects. A schedule editor would need new tables, a responder model, and an acknowledgement loop; nothing else in the product reads it.                    | Portable in a reduced form without people: a per-monitor **channel ladder** (notify A immediately, B after 10 min, C after 30 min, stop on recovery). That needs one table plus a scheduler pass, and reuses the existing channels and retry queue. |
| **Playwright scenario monitoring** — scenario name, scenario body, scenario timeout, Environment variables                                                                  | Create/Configure monitor (monitor types), bulk _Configure Playwright scenario timeout_ | Workers cannot run Playwright; the runtime has no browser engine besides the Browser Rendering binding, which renders pages rather than executing user scripts and cannot be exposed as a user-facing script runner.                                                                            | Portable only as a **fixed** scripted check (no user-supplied script) through the existing `BROWSER` binding, which is deployment-only and already used for outage screenshots.                                                                     |
| **IP version selection** — Both IPv4 and IPv6 / IPv4 only / IPv6 only                                                                                                       | Configure monitor, bulk _Configure IP version_                                         | The check runs on `fetch` in workerd. The runtime chooses the address family; a script cannot request IPv6-only or IPv4-only connects, so the control would be a lie.                                                                                                                           | Not portable on Workers. Self-hosted probes could honour it if the check moved there.                                                                                                                                                               |
| **Region selection per monitor** — Europe / North America / Asia / Australia checkboxes                                                                                     | Create/Configure monitor, bulk _Configure regions_                                     | Regions are owned by probes, not by monitors. The form shows the enabled probe regions read-only and links to the Probes page, where a monitor is switched between the Cloudflare check and multi-region probing. Duplicating the choice in the monitor form would create two sources of truth. | Portable as a filter: keep probes as the roster, add an optional per-monitor include/exclude list that the probe config endpoint respects. Small addition to the existing probe-config query.                                                       |

Everything else in the archived reference set is ported: the workspace shell and design tokens, the monitors list and its selection mode, the per-property bulk dialogs that map onto our fields (frequency, confirmation, recovery, request parameters, request headers, HTTP authentication, SSL/TLS verification, domain expiration, maintenance window, metadata), create/configure monitor including SSL and domain expiry with per-monitor alert thresholds, create heartbeat, monitor detail, incidents, settings, reporting, the public status page and the badge endpoint.

Two reference behaviours are ported with a different surface, on purpose:

- **Test alert / Pause / Remove on the configure page** are icon action links under the monitor name, matching the reference; the dashboard editor mounts the same form and wires the same three actions.
- **Expiration alert thresholds** exist per monitor (1/3/7/14/30 days, default ladder) rather than as separate "SSL expiration" and "Domain expiration" dialogs in the bulk menu; the bulk menu still carries the on/off toggle for each.
